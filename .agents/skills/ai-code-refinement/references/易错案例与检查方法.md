# 易错案例与检查方法

按这些模式判断何时需要补契约、失败注入或独立复核；案例只用于定位检查方向。

## 常见高收益模式

| 模式 | 先查什么 | 最小验证 |
|---|---|---|
| 预检或统计返回固定数量、固定比例 | 字段来源是否来自真实输入；是否存在占位常量 | 空输入、少量输入、损坏输入、数量不一致 |
| 接口宣称发送、保存、发布或完成 | 是否真的调用副作用；是否有异步状态和回执 | 受控 fake sink；断言处理中、成功、失败和重试 |
| 异常后默认值或空列表 | 默认值适用合同；解析失败是否仍可见 | 非法格式、缺字段、超时、半写入文件 |
| 前端只处理成功和空数组 | 失败是否被 catch 丢弃；错误态是否可见 | 4xx、5xx、超时、非法响应 |
| 多条路径复制上传/转换/版本流程 | 哪些是稳定共性，哪些是业务差异 | 同一组边界输入比较错误、清理和产物 |
| 模块同时负责多个副作用 | 输入输出、状态、所有权和失败转移 | 替身外部命令/网络；验证恢复、取消、清理 |

## 证据写法

- **事实**：源代码直接显示的行为，附文件路径和必要行号。
- **静态推断**：由调用点或控制流推得的风险，不能写成已复现缺陷。
- **待运行验证**：需要什么隔离输入、fake 服务或运行环境才能确认。

对已有默认值先问：是否有领域合同？缺省是否合法？解析失败是否被隐藏？规则禁止的是无合同或掩盖损坏输入的回退，而不是所有默认值。
