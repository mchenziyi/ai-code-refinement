# Rust 专项检查

按 `Cargo.toml`、锁文件、edition、features 和实际异步运行时核对；这些检查补充通用规则。

1. **Result、? 与 unwrap**：可恢复错误用 `Result` 和 `?` 保留边界语义；`unwrap/expect` 可用于测试、原型或已证明不变量的内部位置，但生产输入路径要处理失败。验证错误分支和消息是否保留原因。
2. **所有权、clone 与共享**：先划清所有权，再决定借用、移动或 clone；`Arc` 提供线程安全的共享所有权，不自动使内部数据线程安全；需要可变共享状态时另选同步机制。验证 clone 是否改变资源/副作用语义。
3. **锁与 async 边界**：避免阻塞锁 guard 跨 `.await`，用词法作用域尽早释放；短且低竞争的同步临界区可用 `std::sync::Mutex`。确需持锁等待时核对运行时的异步锁，并评估锁顺序和长时间占用，不能统一换成异步锁。验证竞争、取消和锁释放路径。
4. **Drop 与异步清理**：`Drop` 适合同步释放，不能替代需要 await 的关闭协议；异步资源使用项目既有显式 shutdown/flush，并检查 future 被丢弃是否取消底层工作。验证正常、早退和任务取消后的清理与结果。
5. **Cargo 目标与特性**：依据 `Cargo.toml`、`rust-toolchain` 配置、edition、features、目标平台和锁文件使用 API；异步 runtime（如 Tokio）不是标准库默认能力，不凭记忆添加依赖或假定行为。用项目锁定命令验证编译目标和 feature 组合。
6. **unsafe 与并发正确性**：每个 `unsafe` 保留可检查的不变量和最小边界；安全 Rust 的类型检查不能证明无死锁、逻辑竞争或业务错误；unsafe 还须核对内存安全前提。按项目工具和场景做并发/失败行为测试。
