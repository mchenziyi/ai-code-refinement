# Go 专项检查

按实际 `go.mod`、构建约束和运行目标核对；这些检查补充通用规则。

1. **错误包装与接口 nil**：需要向调用方暴露底层错误时，用 `%w` 包装并用 `errors.Is/As` 判断；不依赖错误字符串比较。无错误返回显式 `nil`，不要返回含 nil 指针的非 nil `error` 接口。验证错误链、nil 分支和对外错误语义。
2. **context 与 goroutine 生命周期**：请求、超时或取消会影响后台工作时传递 `context.Context`，创建的取消函数及时调用，并让循环或阻塞操作观察 `Done`；`CancelFunc` 返回不等于工作已停止。核对取消后仍可能完成的副作用，并验证等待退出后不再写入。
3. **channel 关闭职责**：只有明确拥有发送端生命周期的一方关闭 channel；接收者或多个发送者不要抢关。取消可以结束发送而不关闭 channel。验证发送、接收、关闭和取消组合不会永久阻塞。
4. **共享 map 与读改写**：普通 map 涉及并发读写或写写时使用单所有者或互斥；只有并发读不必额外加锁。`sync.Map` 的多步读改写也不自动原子，须保护完整操作；增加 worker 数不构成同步。可用目标项目配置的 `go test -race` 检查竞争。
5. **defer 与释放错误**：`defer` 适合保证关闭，但关闭、flush 或 commit 也可能返回错误；在拥有结果语义的边界保留它，而不是无声丢弃。循环内的 `defer` 到函数返回才执行，逐项资源必要时缩小到独立函数作用域。验证早退和正常路径的释放与必要失败。
6. **range 变量捕获**：闭包捕获循环变量时，先看 `go.mod`、文件构建约束以及变量是用 `:=` 声明还是用 `=` 赋给已有变量；Go 1.22 的新语义不涵盖后一种赋值。按目标版本运行捕获场景测试。
