# Python 专项检查

按实际 Python 版本、事件循环和项目工具链核对；这些检查补充通用规则。

1. **默认参数与可变状态**：函数默认值若为 list、dict 或其他可变对象，会跨调用共享；需每次新建时，用 `None`/专用哨兵在函数内创建；dataclass 字段使用 `default_factory`。若共享是合同则保留并写清。验证连续调用和并发调用的状态隔离。
2. **None、假值与哨兵**：缺失、空字符串、零和 `None` 不一定同义；涉及业务状态时用 `is None` 或专用哨兵明确区分，避免 `value or default` 覆盖合法的零或空值。验证每种输入的分支和序列化结果。
3. **异常边界与 cause**：把 `try` 限定在预期失败的操作，只处理能恢复或转换的异常；转换时按需要用 `raise ... from exc` 保留原因。EAFP 的预期分支可正常处理，不把无关缺陷转成默认成功。验证原异常、上下文和对外错误信息。
4. **asyncio 任务取消**：创建任务后保存所有权、等待结果并处理取消；清理后通常继续传播 `CancelledError`，不要无条件吞掉。验证超时、取消、正常完成和资源清理顺序。
5. **事件循环中的阻塞调用**：阻塞 I/O 和长 CPU 计算不能因位于 `async def` 就自动并行；按项目机制把阻塞 I/O 移到线程、CPU 工作移到合适执行边界，线程不保证 Python CPU 计算并行。一次性脚本可以接受同步成本。验证高延迟操作不会阻塞必须响应的任务。
6. **上下文管理器**：文件、锁、临时状态等有明确生命周期时使用 `with`/`async with` 或等价清理；`finally` 中不要掩盖原异常。验证初始化失败、主体异常和清理失败的结果。
