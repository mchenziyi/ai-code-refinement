# Node.js 生态专项检查

仅在确认目标是 Node.js 运行时的 JavaScript/TypeScript 项目时读取；浏览器代码不能仅凭 `.js`/`.ts` 后缀套用这些规则。

1. **Promise 链与异步迭代**：完成状态依赖的 Promise 须返回或 `await`；有意后台运行的任务也须有错误和生命周期处理者。`forEach(async ...)` 不等待回调，改用 `for...of` 或项目约定的并发组合。验证失败是否到达调用方以及任务是否全部完成。
2. **Promise 组合的取消语义**：`Promise.all/race` 只组合观察结果，不自动停止其他工作；需要取消时使用目标 API 支持的 `AbortSignal` 或项目协议，并处理已发出的副作用。验证超时后后台任务和资源状态。
3. **Streams 背压与错误**：正常 `write()` 返回 `false` 表示已接收但需暂停继续写，不要重发同一块；流已损坏或关闭时须走失败路径。恢复须考虑 `drain` 和错误/关闭。多段流组合优先用 `pipeline()`，核对结束时是否会销毁下游。验证慢消费者、下游失败和清理；写入完成不等于持久化。
4. **错误传播与事件**：为异步边界保留 `cause`、错误码和必要上下文；会发出 `error` 的 EventEmitter 须有明确处理者，不能用空 catch 或未处理 rejection 表示成功。验证错误到达正确边界且不泄露敏感值。
5. **事件循环与同步操作**：服务请求热路径和交互任务评估 CPU/同步 I/O 是否阻塞事件循环；一次性 CLI 或启动阶段可以接受同步成本。用目标运行方式检查响应性和大输入行为。
6. **模块与运行目标**：根据 `package.json` 的 `type`、`exports`、`.mjs/.cjs`、Node 版本和实际构建配置选择 ESM/CJS/TypeScript 用法；浏览器 bundle、测试运行时和服务运行时分别核对入口，不能凭根目录文件后缀判断。
