# 安全与依赖

处理外部输入、权限、秘密或引入依赖前读取。

## S-01 SQL 值使用参数绑定

值条件通过数据库驱动的占位符和绑定值传入，不能把输入拼进 SQL 字符串。表名、列名和排序方向通常不能作为普通值参数绑定；动态标识符须从固定允许列表映射到已知 SQL 片段，不能直接信任用户字符串。参数化仍须遵守授权和查询范围合同。

## S-02 命令执行分离参数并约束选项语义

使用进程 API 的程序与参数数组，避免把输入拼进 shell 命令行；如平台/接口提供，应使用参数结束标记阻止以 `-` 开头的用户值被解释为选项，并对允许命令、文件路径和参数范围采用白名单。分离 argv 能减少 shell 解释风险，但不自动防止参数选项注入或危险子命令。

## S-03 输出编码按目标上下文选择

输出到 HTML、属性、URL、JavaScript、CSS 或其他解释器时使用对应上下文编码/安全模板，不能用一次通用转义解决所有上下文。SQL、shell 和 HTML 的转义规则不可互换；优先使用参数化或专门 API。

## S-04 路径校验针对最终目标边界

将外部路径限制在合同授权根目录下；先规范化并验证边界关系，避免仅做字符串前缀比较。若威胁模型包含并发替换或符号链接，采用目标平台提供的安全打开/目录句柄方式避免校验后路径被替换。可信内部固定路径不需重复做复杂防护。

## S-05 每个请求在服务端校验对象级授权

执行读写或其他受保护操作时，在服务端以当前身份、动作和具体对象核验授权；仅在界面隐藏按钮或依赖上游曾做过检查不够。授权所需字段来自可信身份上下文而非请求自报。没有定义角色/策略时先澄清，不推测默认权限。

## S-06 秘密不得进入诊断或产物

凭据、令牌、密钥和个人敏感数据只在必要边界传递。日志、错误、快照和测试产物使用非敏感标识及虚构测试值；禁止打印完整请求头、环境变量或未经筛选的对象。错误信息不得回显秘密输入。

## S-07 依赖 API 按目标版本核对

引入依赖前检查已有能力、项目维护状态、目标平台及许可要求；按项目规则更新 manifest 和锁文件。调用 API 前核对目标环境实际安装版本的官方文档、本地类型或实现，不凭模型记忆或宿主机另一版本推断。一次性简单逻辑可清晰本地完成时不添加依赖。

## S-08 安全验证匹配具体攻击面

只针对本次触及的输入、对象授权、命令、路径或秘密边界验证实际相关风险。纯内部变更无需泛化增加安全设施；静态扫描通过不能替代关键授权/输入边界的行为验证。
