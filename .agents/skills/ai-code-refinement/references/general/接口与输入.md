# 接口与输入

实现接口、解析外部数据或改变序列化行为前读取。服从项目协议与目标平台的既有合同。

## I-01 按使用风险验证必填项、类型与范围

在请求入口、消息消费、文件读取、环境变量或第三方响应进入业务前，检查合同要求的必填项、类型、数值范围、格式和枚举。只校验后续实际使用的约束；不可解析的字段不得以零值代替。校验失败在边界返回稳定可识别的字段错误，不能暴露载荷中的秘密。

## I-02 对长度、容量和成本设合同上限

对可能被外部控制且会分配内存、递归处理、写入批次或触发昂贵计算的长度/数量，采用项目已有上限或已确认的安全上限；在分配或处理之前检查。限制与产品支持范围冲突时先确认策略，不悄悄截断输入。无需对可信且有界的固定内部结构添加重复上限。

## I-03 校验顺序应先做廉价检查，再执行昂贵或有副作用操作

先验证语法、必填和大小，再执行数据库查询、远端调用、文件写入等较贵或有副作用的步骤；授权检查需在受保护对象操作前完成，若授权须先读取对象则确保读取本身不会泄露内容。检查与使用之间可能被并发修改时，在真正改变状态的边界重新核验条件。

## I-04 缺失、null、未知值和非法值不得随意合并

字段缺失、显式 null、空值、未知枚举与格式错误只有合同声明等价时才能归一。未知字段可按协议选择保留、忽略或拒绝：前向兼容的扩展字段可能需要保留或忽略；签名字段、写命令字段或严格版本协议可能必须拒绝。遵循真实协议并记录选择依据，不采用“一律忽略”或“一律拒绝”。

## I-05 公共接口定义成功阶段和失败类别

核对真实调用方，定义成功是已完成、已接受还是仍处理中，并为可纠正输入、权限拒绝、冲突和服务故障提供可判别语义。成功消息只能在合同对应的工作实际完成/受理后返回；没有实现的副作用不得用空函数或固定成功响应伪装完成。若只实现局部范围，明确返回未实现或失败状态。

## I-06 分页必须有稳定排序和续页语义

确认页大小范围、排序稳定性、游标/偏移含义、边界是否包含及数据变化时的可见性。游标应包含稳定排序键及必要的并列键；不得根据无序映射或数据库未保证的行序生成续页标记。未被合同要求时不增加总数查询或固定页大小行为。

## I-07 序列化精确保留字段合同

核对字段名、单位、时间格式、精度、空态和未知字段政策。签名、缓存键、去重键或比较所用序列化应有确定规范化形式。改变字段含义、删除字段或改变默认值前检查旧客户端、存量数据和版本机制；增加字段不能单独证明兼容。

## I-08 验证真实协议结果

以真实协议形状检查状态码/结果分类、字段和序列化值，包括与本次改动相关的非法、缺失及边界输入。可用最小请求或服务边界替身；纯转换已有隔离测试足以证明时不增加端到端环境。断言用户合同，而非某个内部校验函数被调用。
