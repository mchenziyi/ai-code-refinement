# 跨语言通用规则与语言案例

按当前改动风险读取相关条目；小改动只取必要检查，不因语言出现就强制抽象、异步、并发框架、长文档或全量测试。

## 1. 业务语义、单位和状态命名

- **触发**：名字丢失金额单位、时区、状态或角色，或相近概念被宽泛工具混用。
- **执行**：遵循仓库和目标语言惯例，让公开数据和状态名表达角色、单位、状态或边界；不把一种语言的命名形式套到其他语言。
- **核验**：对照调用点、序列化字段和边界案例检查语义；不能以命名检查通过推断业务正确。Go 导出命名、Python/JS/TS/Rust 惯例各自核对。

## 2. 复用与抽象的稳定边界

- **触发**：为一次性逻辑抽出万能工具，隐藏差异并增加耦合，或复制已有能力造成行为漂移。
- **执行**：先搜已有实现、调用点和变化频率；只有契约和变化原因稳定时复用。一次性逻辑留在局部。封装须显式保留或说明对错误、取消、单位和副作用合同的转换，不能静默改变语义。
- **核验**：检查已有调用方、差异和异常路径，并对比改动前后的调用点和契约测试；不能以“复用了”本身证明质量提升。

## 3. API、模块和职责契约

- **触发**：一个入口同时解析输入、做业务决策、持久化和外部副作用，或改动只看定义不看调用者。
- **执行**：列明输入、输出、错误、资源所有者和副作用，再按变更边界做最小拆分；读取实际版本的 API、配置和 schema。
- **核验**：沿调用方和集成边界检查职责、失败和副作用；不能以文件大小单独判定需要拆分。模块/package/crate 的具体形式按项目工具链落实。

## 4. 外部输入、类型和序列化

- **触发**：把类型注解、编译器或 schema 名称当作运行时校验，导致缺字段、非法单位、未知枚举或恶意输入进入业务。
- **执行**：在信任边界运行时解析、校验、归一化和报告错误；明确未知字段、null、版本和单位策略。
- **核验**：用缺失、非法、未知版本和单位案例检查输入与序列化语义；不能仅看静态类型通过。Python 注解不替代运行时校验，Node.js 生态的 JavaScript/TypeScript 项目也须校验外部数据。

## 5. 错误、预期失败与部分结果

- **触发**：吞掉异常、混淆预期拒绝和系统故障，或批处理中静默丢弃记录。
- **执行**：按目标语言惯例区分可恢复/预期失败和意外失败，保留原因与上下文；有合同允许跳过时返回拒绝计数/原因或显式部分结果。
- **核验**：依据调用合同检查输出和拒绝计数，覆盖正常、边界和失败路径；不能把“捕获了异常”称为处理完成。Python 可按 EAFP 直接尝试并处理异常，不强制 Java 式预检查。

## 6. 取消、截止时间和异步任务所有者

- **触发**：任务丢失取消信号、超时后仍写副作用，或创建异步任务却无人等待/回收。
- **执行**：任务确有等待、外部 I/O 或并行风险时，明确谁创建、谁等待、谁取消以及完成状态如何传播。取消请求不等于工作已停止、资源已清理或副作用已回滚。
- **核验**：用可控超时和取消测试检查任务所有权、完成状态、清理和副作用状态。Go CancelFunc、Python cancellation、Node AbortController 都须按实际 API 理解；Rust 异步运行时需看项目配置，不能默认引入 Tokio。

## 7. 资源所有权、关闭和清理

- **触发**：文件、连接、线程、进程、锁或 stream 的所有者不明，异常或取消路径泄漏或重复关闭。
- **执行**：声明创建者、使用者和释放者，覆盖正常、异常和取消路径；按项目机制落实 context manager、pipeline、Drop、defer/Close 等清理。
- **核验**：检查实际资源状态和可重复释放语义；不能只凭语法形式判断无泄漏，也不能把 Rust ownership 当作业务或死锁保证。

## 8. 并发、背压和有界工作

- **触发**：无界创建任务或缓冲、生产快于消费、共享状态竞态、等待无人收集或错误传播缺失。
- **执行**：仅在并发/流式风险存在时设置有界工作、取消和背压，并定义拒绝或排队语义；不规定统一并发数。Go channel 不必总是 close。
- **核验**：用慢消费者、取消、失败和关闭案例验证；不能以使用 channel、async 或 ownership 推断正确。Node stream 的 drain/pipeline、Python task/queue、Rust 线程/共享状态等具体机制按项目配置落实。

## 9. 外部副作用、重试与幂等

- **触发**：网络、队列或写入失败后盲目重试，造成重复操作或状态覆盖。
- **执行**：先确认副作用合同、幂等键、可重试错误和尝试边界；只对合同允许的操作重试，记录最终状态。
- **核验**：检查真实服务合同和重复请求结果，确认幂等后再重试；不能仅凭异常可捕获就重试。

## 10. 依赖、版本和真实 API

- **触发**：凭记忆调用不存在或不兼容的 API，本地配置和包入口与目标环境不同。
- **执行**：读取 manifest、锁文件、配置和已安装版本，再使用实际 API；需要复现时保留命令输出。一次性 CLI/启动阶段可接受同步阻塞成本，服务热路径和交互任务需评估响应性。
- **核验**：运行最小真实调用或契约检查，不能只做字符串或类型匹配。Go modules、Python 环境、Node package.json/exports/type、Rust Cargo 的实际配置各自核对。

## 11. 行为证据与验证层级

- **触发**：只通过编译、只测自选假设或只镜像实现细节，漏掉契约、边界、失败和副作用。
- **执行**：按风险选择单元、契约、集成或端到端验证；测试依据确认过的合同，按任务保留必要结果和未验证项，失败或需要复现时给出命令。
- **核验**：不能把静态检查或“tests OK”写成业务验收；用独立合同和真实行为证据核验业务行为。
