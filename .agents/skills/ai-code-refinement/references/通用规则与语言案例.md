# 跨语言通用规则与语言案例

按当前改动风险读取相关条目；小改动只取必要检查。

## 1. 业务语义、单位和状态命名

- **触发**：名字丢失金额单位、时区、状态或角色，或相近概念被宽泛工具混用。
- **执行**：遵循仓库和目标语言惯例，让公开数据和状态名表达角色、单位或边界，不跨语言机械套用命名形式。
- **核验**：对照调用点、序列化字段和边界案例检查语义；命名检查不能证明业务正确。

## 2. 复用与抽象的稳定边界

- **触发**：为一次性逻辑抽出万能工具，隐藏差异并增加耦合，或复制已有能力造成行为漂移。
- **执行**：先搜已有实现、调用点和变化原因；契约和变化原因稳定时再复用，一次性逻辑留在局部。封装须保留或说明错误、取消、单位和副作用合同的转换。
- **核验**：对比已有调用方、业务差异和异常路径；不能以代码变短或“复用了”本身证明质量提升。

## 3. 变更范围、职责与兼容

- **触发**：一个入口承担多个变化原因，或改 API、配置、数据格式、默认值和行为却只看定义。
- **执行**：沿调用方确认输入、输出、错误、资源所有者和副作用，只做任务必需拆分。保留既有契约；确需破坏性变更时确认迁移、版本和过渡要求，不顺手重构或弱化断言来消除回归。
- **核验**：检查完整 diff，说明必要变更；对照旧调用、配置和存量数据验证兼容。新增字段、文件变小或测试改绿都不能单独证明兼容。

## 4. 外部输入、类型和序列化

- **触发**：把类型注解、编译器或 schema 名称当作运行时校验，导致缺字段、非法单位、未知枚举或恶意输入进入业务。
- **执行**：在信任边界解析、校验、归一化和报告错误；明确未知字段、null、版本和单位策略，按实际下游使用参数化或转义。
- **核验**：用缺失、非法、未知版本和单位案例检查输入与序列化语义；静态类型通过不能替代运行时检查。

## 5. 业务状态与不变量

- **触发**：改动涉及状态流转、余额/库存等约束、重复执行或跨步骤业务决策。
- **执行**：从已确认需求、合同和调用点确定合法转换、前置条件及必须始终成立的约束；不自行发明状态机。关键定义不明先澄清，在真正改变状态的边界执行约束。
- **核验**：覆盖合法转换、非法转换、重复执行和失败后的状态；检查不变量，而不只断言接口返回成功。

## 6. 错误、部分结果与诊断

- **触发**：异常被吞、批处理静默丢记录、日志无法定位原因，或每层重复记录同一错误。
- **执行**：区分预期拒绝、系统故障、空态和有合同的回退，保留原因链。允许跳过时返回拒绝计数/原因或显式部分结果；在能采取行动的边界记录必要操作、标识和阶段，避免重复日志、敏感值和完整对象 dump，不为小任务引入日志平台。
- **核验**：注入失败，确认调用方和维护者能区分结果并找到根因；核对拒绝计数和日志脱敏。捕获异常不代表处理完成，已受理不代表已完成。

## 7. 取消、截止时间和异步任务所有者

- **触发**：任务丢失取消信号、超时后仍写副作用，或创建异步任务却无人等待/回收。
- **执行**：明确谁创建、等待和取消任务，以及完成和失败如何传播；取消请求不等于已停止、已清理或已回滚。
- **核验**：用可控超时和取消检查任务退出、清理和副作用状态；按实际 API 核对，不能假定所有操作都响应取消。

## 8. 资源所有权、关闭和清理

- **触发**：文件、连接、线程、进程、锁或 stream 的所有者不明，异常或取消路径泄漏或重复关闭。
- **执行**：明确创建者、使用者和释放者，按实际机制覆盖正常、异常和取消路径；需要显式 flush/shutdown 的协议不能只靠对象销毁。
- **核验**：检查资源状态、关闭失败和重复释放语义；不能仅凭 defer、with、Drop 等语法判断无泄漏。

## 9. 共享状态、并发与背压

- **触发**：共享读改写、检查后再操作、无界任务/缓冲、慢消费者或错误无人收集。
- **执行**：围绕完整不变量选择单所有者、锁、原子操作或版本条件，避免只保护单次读写却遗漏整体操作；异步交错也可能造成更新丢失。仅在风险存在时设置有界工作、背压和排队/拒绝语义，不统一规定并发数或给所有对象加锁。
- **核验**：用可控交错、竞争、慢消费者、失败和取消验证丢失更新、重复执行、死锁及清理；无数据竞争报告不等于业务并发正确。

## 10. 外部副作用、重试与幂等

- **触发**：网络、队列或写入失败后盲目重试，造成重复操作或状态覆盖。
- **执行**：确认副作用合同、幂等键、可重试错误和尝试边界；只有合同允许才重试。响应丢失时区分“未执行”和“执行结果未知”，必要时查询或对账。
- **核验**：检查真实服务合同，模拟重复请求与已生效但响应丢失；异常可捕获不代表可安全重试。

## 11. 多步写入、一致性与恢复

- **触发**：多条数据、文件与数据库或外部服务需共同更新，中途失败会留下半完成结果。
- **执行**：确定原子边界、步骤顺序和成功判定，按实际存储合同选择事务、原子替换、补偿或可恢复状态；明确已生效、待确认和未执行的步骤及恢复方式。跨服务不强行套本地事务；原子 rename 不等于断电持久化，取消不等于回滚。
- **核验**：在关键步骤失败后检查实际数据、对外状态和再次执行；验证恢复/补偿本身失败时仍可识别并继续处理，不能只测全成功路径。

## 12. 依赖、版本和真实 API

- **触发**：凭记忆调用不存在或不兼容的 API，本地入口、配置与目标环境不同。
- **执行**：读取 manifest、锁文件、配置和实际安装版本，再核对 API 与运行目标；不为一次性工作引入不必要依赖。
- **核验**：运行最小真实调用或契约检查；字符串匹配、编译通过和宿主机版本不能证明目标环境兼容。

## 13. 有用且同步的注释

- **触发**：代码包含非显然业务限制、算法取舍、兼容原因或失败处理，或改动使原注释失效。
- **执行**：注释说明原因、约束或失败条件，随行为同步更新；明显的赋值、循环和函数名不逐行复述，稳定契约优先放在公开入口而不复制到各处。
- **核验**：对照当前实现和合同检查注释是否真实；能删去而不损失理解的信息不补写，不为注释调整无关代码。

## 14. 行为证据与验证层级

- **触发**：只通过编译、只测自选假设或只镜像实现细节，漏掉契约、边界、失败和副作用。
- **执行**：按风险选择单元、契约、集成或端到端验证；断言依据确认的需求和既有合同，保留必要结果与未验证项，失败或需要复现时给命令。
- **核验**：用独立合同和真实行为证据检查结果；静态检查或“tests OK”不能写成业务验收。
