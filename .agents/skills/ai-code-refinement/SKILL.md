# AI 代码精炼之道

适用于实现功能、修复缺陷和审查改动。遵循用户、项目和目标语言约定；小改动不要求长文档、全量测试或额外协作。

## 8 条规则

1. **先确认需求、范围和兼容。** 明确可观察的成功标准、输入输出、失败语义和范围；只改必要内容，检查无关 diff。涉及单位、权限、数据丢弃、公共 API、配置、数据格式或既有行为时查调用方和迁移要求，关键歧义未消除就澄清，不自选业务默认值、不弱化测试来交付。
2. **先查已有实现和真实 API。** 搜索调用点、类型/schema、配置、测试和必要的 manifest/锁文件，再决定复用或新建；核对实际版本和工具链，不凭记忆猜 API。
3. **复用、命名和注释表达稳定语义。** 一次性逻辑留在局部；封装须保留或说明错误、取消、单位和副作用合同的转换。遵循仓库与目标语言惯例，让名字表达角色、单位、状态和边界；注释只写非显然原因、约束或失败条件，并随变更更新。
4. **职责、输入合同和业务不变量清楚。** 按输入、输出、错误、资源所有者和副作用划分最小变更边界；在信任边界运行时校验输入、单位、schema 和序列化语义。依据已确认合同列出合法状态转换和不可破坏约束，不由模型发明业务状态，静态类型不替代校验。
5. **错误和成功状态真实且可诊断。** 区分预期失败、意外错误、空态和有合同的回退；批处理跳过时给拒绝计数/原因或部分结果。成功只表示已完成的检查或副作用，异步要明确为已受理或处理中；保留原因和最小定位上下文，必要时在合适边界记录一次，不泄密或 dump 全对象。
6. **资源、写入和任务有所有者。** 按风险落实安全 API、敏感值保护、清理、任务等待、超时和取消；取消请求不等于已停止或回滚。多步写入明确已生效步骤和失败恢复，按存储合同选择事务、原子替换、补偿或可恢复状态。共享读改写须整体协调；并发/流式场景才设置有界工作和背压。
7. **副作用与测试依据合同。** 外部副作用重试前确认幂等合同、幂等键和边界；按风险选择单元、契约、集成或端到端验证，断言依据用户需求或既有合同，新增字段不等于兼容。
8. **交付证据可核验。** 覆盖必要的正常、边界和失败路径；按任务保留必要结果和未验证项，失败或需要复现时给出命令。不把编译、自选假设或未执行的检查称为业务验收。

## 按风险读取详细资料

需要细节时按问题读取[通用规则与语言案例](references/通用规则与语言案例.md)；定位真实项目模式时读取[易错案例与检查方法](references/易错案例与检查方法.md)。

根据改动组件的 manifest、工具链和运行目标选读专项规则：[Go](references/languages/go/go.md)、[Python](references/languages/python/python.md)、[Node.js](references/languages/nodejs/nodejs.md)、[Rust](references/languages/rust/rust.md)。混合项目分别选择；Node.js 须确认运行目标，不能仅凭 `.js`/`.ts` 或根目录 `package.json` 套用到浏览器代码。其他语言继续使用通用规则并核对自身官方约定。
