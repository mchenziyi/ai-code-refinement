# AI 代码精炼之道

## 编码前与编码中

开始修改前先确认用户目标、可观察结果、范围及兼容边界；若基础规范正文尚未在当前上下文中，先阅读[基础开发规范](references/general/基础开发规范.md)，随后在编码全过程遵循。先搜索相关入口、调用方、数据合同、测试和项目既有实现，再确定局部修改方式。需求或业务默认值存在关键歧义时先澄清。

实现过程中，根据正在处理的内容先读相应场景规范，再编写该部分代码：

- 对外接口、消息、文件格式、用户或第三方输入：[接口与输入](references/general/接口与输入.md)
- 错误传播、部分结果、任务生命周期和外部资源：[错误与资源](references/general/错误与资源.md)
- 共享状态、并发处理、重试和多步持久化写入：[并发与持久化](references/general/并发与持久化.md)
- 信任边界、权限、敏感信息或依赖：[安全与依赖](references/general/安全与依赖.md)
- 设计合同断言和可重复验证：[验证与测试](references/general/验证与测试.md)

按改动所触及的主题组合阅读；纯局部变更只需基础规范及实际相关场景。场景规则用于指导实现方式，不要求为不存在的风险增加机制。完成后按需求与项目合同验证行为，并如实交付已验证结果和未验证边界。
