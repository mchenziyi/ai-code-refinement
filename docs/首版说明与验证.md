# v0.1 首版说明与验证

本版本把跨语言 AI 辅助开发收敛为 8 条规则，覆盖编码前的真实实现/API核对、关键业务歧义澄清、业务命名、稳定共性抽象、职责边界、错误/空态/有合同回退、成功状态真实性、风险触发的安全与资源检查、分层测试和真实交付证据。它不要求每个小改动写设计书、全量测试、画图或委派代理。

Skill 入口为 `.agents/skills/ai-development-handbook/SKILL.md`；UI 元数据在同目录 `agents/openai.yaml`；两份按需读取的资料在 `references/`。安装方式是把 `.agents/skills/ai-development-handbook` 放入目标项目的 `.agents/skills/` 或用户已配置的 Skill 目录；复制前先检查目标是否已有同名目录，不覆盖已有内容，也不做全局自动安装。

## 首轮独立前向试用记录

首轮评估代理在隔离的标准库订单摘要 fixture 上完成了 2 个自选测试，但业务验收未通过：它自行把默认报告币种设为 USD 且没有来源配置；缺字段、非法金额和异币种记录用 `continue` 静默丢弃；既有总额语义从包含 pending 变成不包含 pending，却仍称保持兼容。首轮测试只证明了执行者自己的业务假设。

第二轮是同一评估者针对性复核，不是新的盲测。它去掉了默认 USD，将未知币种输出为 `null`，并增加 `rejected_records` 与 `rejection_reasons`；主代理独立复跑 `python3 -m unittest -v test_app.py`，实际结果为 3 tests OK。因此本轮属于部分改善，业务验收仍未通过/未完成：`gross_sales` 的计算定义未经业务确认，旧字段兼容性因 `total` 语义变化仍未验证，未知报告币种和跨币种的完整语义也未确认。3 个测试只是执行者自选行为测试，不是独立业务验收，更没有 A/B 对照。

练习材料只位于本机临时目录，未保存为可移植基准集。后续应先冻结明确的业务合同，再由独立验收测试验证；本首版是可试用草案，不是质量保证工具。

## DSH bundle 验证

本版本新增最小 native Cordis bundle：`package.json` 的 `dsh.bundle.patch` 插入 `ai-development-handbook-dsh`，`index.js` 读取同包 `.agents/skills/ai-development-handbook/SKILL.md`，去除 frontmatter 后通过 rc.2 的 `ctx.systemPrompt.section()` 注册一个非 `complete` section。资源读取失败时插件 fiber 进入 `FiberState.FAILED`，不会注册空 section。

本机以 DSH `0.2.0-rc.2`、Node `v24.12.0` 运行了真实 Cordis + `dsh-system-prompt` + `cordis-plugin-loader` 测试：注册后重复 `assemble()` 只有一份 section；Loader 加载、禁用、重载和移除均通过；缺少 Skill 资源时 fiber 为 failed 且 assemble 不含该 section。可复跑：

```sh
DSH_RUNTIME_ROOT=/path/to/@deepseek-ai/dsh \
  node --test --test-timeout=30000 test/native-loader.test.mjs
```

`npm pack --dry-run --json` 确认 tgz 包含入口、patch、Skill、metadata 和两份 references 共 8 个文件。实际临时包位于仓库外 `/tmp/ai-development-handbook-dsh-0.1.0.tgz`，SHA-256 为 `0d0da4083d52b1e97fc9373fd5b77b1e9a6e3101a0fc5ab46837d4485b24d03b`；该文件不是仓库产物。尚未在临时 `DSH_HOME`/profile 走 `dsh plugin add` 安装闭环，也未调用在线 LLM、Web 或真实 UI。

注入作用于继承同一 prompt registry 的 scope；具有 scoped `complete` system prompt 的 preset 可以合法排除外部 section。已静态核对 rc.2 默认 bundle 中 Skill、Team policy 和 persona 的注册方式，但没有做默认 coder/creator/team 或 ACP 端到端验证，因此不能把本测试称为真实团队会话验收。
