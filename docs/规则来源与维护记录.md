# 规则来源与维护记录

## 阿里《Java 开发手册》

来源落地页：[泰山版](https://developer.aliyun.com/ebook/330)、[嵩山版](https://developer.aliyun.com/ebook/394)。两版是同源修订，主要可迁移的是问题机制：需求边界与异常流程（设计规约 §8）、职责/组合/抽象与共性复用（设计规约 §9–13）、公共接口兼容（OOP 规约 §4–5）、错误处理（异常处理 §1–4）、日志现场与重复输出（日志规约 §6–11）、自动/独立/可重复和边界/错误测试（单元测试 §1–9）、参数化输入和脱敏（安全规约 §1–5）。

这些条款是传统开发规范，不是 AI 专属要求。Javadoc、POJO、`@Override`、Java 异常控制流、`System.out` 的特定旧环境限制、Maven SNAPSHOT、MySQL/iBATIS、线程池和 `ThreadLocal` 等不能直接套用到 Python、TypeScript、Rust 或其他运行时。覆盖率数字也不能代替风险导向的集成验证。

## vArmor 项目规范

来源：[vArmor AGENTS.md](https://github.com/bytedance/vArmor/blob/main/AGENTS.md)，本轮资料读取时间为 2026-10-21；在线 `main` 未固定到不可变 commit，不能当作稳定版本承诺。它是 vArmor 项目规范，不代表字节全公司规范。

可迁移的是显式错误返回和上下文、结构化日志与 Secret 不入日志、成功/失败测试、输入入口校验加下游转义、并发共享状态与资源关闭、生成物和契约链核对。Go、Kubernetes、eBPF、Webhook、YAML 字符集、Kubernetes Secret 和 `make` 命令属于项目或技术栈专属案例。

## AI 特有缺口

传统规范不能解决需求理解、业务正确性、幻觉 API、上下文丢失、漏执行工具、伪造完成、自证偏差、环境依赖、并发协作和效果评测。手册只提供可借鉴的开发检查点；AI 流程还必须依据用户授权和项目约定记录实际证据。

## 语言规则官方资料

对应 `references/languages/` 中的专项规则；具体 API 与行为以目标项目版本为准。

- Go：[Effective Go](https://go.dev/doc/effective_go)、[Context](https://go.dev/blog/context)、[Go 1.13 Errors](https://go.dev/blog/go1.13-errors)、[Managing dependencies](https://go.dev/doc/modules/managing-dependencies)、[CancelFunc](https://pkg.go.dev/context#CancelFunc)、[nil error FAQ](https://go.dev/doc/faq#nil_error)、[Go 1.22 循环变量](https://go.dev/doc/go1.22#language)、[Data Race Detector](https://go.dev/doc/articles/race_detector.html)。Effective Go 是较早的风格资料，不作为现代泛型或 module 事实的唯一依据。
- Python：[Exceptions](https://docs.python.org/3/library/exceptions.html)、[asyncio tasks](https://docs.python.org/3/library/asyncio-task.html)、[Python 3.14 cancellation](https://docs.python.org/3.14/library/asyncio-task.html#task-cancellation)、[contextlib](https://docs.python.org/3/library/contextlib.html)、[typing](https://docs.python.org/3/library/typing.html)、[默认参数](https://docs.python.org/3/tutorial/controlflow.html#default-argument-values)、[dataclass 默认工厂](https://docs.python.org/3/library/dataclasses.html#dataclasses.field)、[真值判断](https://docs.python.org/3/library/stdtypes.html#truth-value-testing)、[异常处理与链](https://docs.python.org/3/tutorial/errors.html)。
- Node.js：[Don't block the event loop](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop)、[Errors](https://nodejs.org/api/errors.html)、[Streams](https://nodejs.org/api/stream.html)、[Packages](https://nodejs.org/api/packages.html)、[AbortController](https://nodejs.org/api/globals.html#class-abortcontroller)。仅适用已确认以 Node.js 为运行目标的组件，不能套用到浏览器组件。
- Rust：[Ownership](https://doc.rust-lang.org/book/ch04-00-understanding-ownership.html)、[Error handling](https://doc.rust-lang.org/book/ch09-00-error-handling.html)、[Concurrency](https://doc.rust-lang.org/book/ch16-00-concurrency.html)、[Shared state](https://doc.rust-lang.org/book/ch16-03-shared-state.html)、[Smart pointers and Drop](https://doc.rust-lang.org/book/ch15-00-smart-pointers.html)、[Why Cargo exists](https://doc.rust-lang.org/cargo/guide/why-cargo-exists.html)、[panic 的适用边界](https://doc.rust-lang.org/book/ch09-03-to-panic-or-not-to-panic.html)、[Arc 线程安全](https://doc.rust-lang.org/std/sync/struct.Arc.html#thread-safety)、[Drop](https://doc.rust-lang.org/std/ops/trait.Drop.html)、[Tokio 共享状态](https://tokio.rs/tokio/tutorial/shared-state)。Rust 异步运行时不属于标准库默认能力。
- JavaScript Promise 组合与异步迭代：[ECMAScript Promise.all](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise.all)、[Promise.race](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise.race)、[Array.prototype.forEach](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-array.prototype.foreach)。这些机制也适用于其他 JavaScript 运行环境；Node.js 文件把它们与 Node 任务、流和事件边界一起检查。
